# DevOrbit — Connection Protocol Specification

## 1. Frame Envelope Structure

All WebSocket messages routed through the Connection Broker use a standardized, binary-friendly JSON frame envelope:

```json
{
  "v": "1.2",
  "session_id": "sess-a1b2c3d4",
  "type": "data",
  "encrypted_payload": "a1f87c9e0d1f3b...",
  "seq_num": 1042
}
```

### Frame Fields
- `v`: Protocol version string (`"1.2"`).
- `session_id`: Session ID generated by Control Plane upon session authorization.
- `type`: Frame type indicator (`"data"`, `"ping"`, `"pong"`, `"close"`).
- `encrypted_payload`: Hex-encoded AES-256-GCM ciphertext payload encrypted with the session's E2E symmetric key.
- `seq_num`: Monotonically increasing sequence number for replay protection and packet ordering.

## 2. Reconnection & Recovery Algorithm

1. **Heartbeat Monitoring**: Ping frames emitted every 15 seconds. If no pong response is received within 30 seconds, connection state transitions to `reconnecting`.
2. **Exponential Backoff**: Initial retry delay = 1s. Multiplier = 2.0. Max delay = 30s. Jitter = ±20%.
3. **Session Revalidation**: Upon reconnecting, client submits session token. If session has expired or device was revoked, connection transitions to `revoked`/`expired`.
